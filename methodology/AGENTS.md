# Methodology editorial instructions

These instructions apply to the public methodology pages under `methodology/`.
Follow [EDITING.md](EDITING.md) when proposing changes.

- Write for external analysts and researchers. Explain data, assumptions,
  calibration and limitations in connected prose.
- Preserve the reviewed structure and audience. Make focused edits for the
  requested methodological change; propose a reorganisation separately.
- Keep commands, build logs, issue histories, gate identifiers and implementation
  procedures in the Microcosm implementation repository. Link to them when useful.
- Check mechanism claims against the relevant source code or source manifest.
  Pin references to a commit or release wherever possible.
- Identify the dataset release behind any measured statistic. Do not copy metrics
  from a different release or describe planned or inspection-only methods as a
  certified production dataset.
- Household copies are not additional independent observations. Describe record
  counts, source-household support and effective sample size distinctly.
- Request editorial and technical review before publishing substantive changes.
  Passing automated checks is not editorial approval.
- Preserve the current site styling and static Vercel deployment. A methodology
  edit does not require a site redesign or a new frontend framework.
